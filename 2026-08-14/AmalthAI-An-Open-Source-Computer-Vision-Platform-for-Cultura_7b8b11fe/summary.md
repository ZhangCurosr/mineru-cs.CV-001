# 论文速读：AmalthAI: An Open-Source Computer Vision Platform for Cultural Heritage

## 一句话总结
AmalthAI 是一个面向文化遗产（CH）领域专家的开源计算机视觉平台，通过无代码 Web 界面支持图像分类、语义分割和目标检测的端到端流程，并结合 Grad-CAM 与视觉-语言模型（VLM）提供可解释性支持，使非 ML 专家能够在数据不出机构的前提下独立完成模型训练、验证与考古假设检验。

## 研究问题与动机
1. **领域专家访问壁垒**：CV/ML 流水线通常需要数据集准备、模型配置、参数调优和软件工程经验，而文化遗产学者的核心专长并不在此，现有工具对他们过于复杂。
2. **无代码平台与数据主权冲突**：面向非技术用户的 no-code 平台（如 Roboflow、Ultralytics）默认依赖供应商云端，而考古图像常受所有权或分发政策限制，不允许离开机构本地托管。
3. **评估-验证鸿沟**：现有工作通常停在准确率指标层面，缺少让领域专家"质疑"模型决策依据的工具，无法判断预测是否正确、是否基于考古相关的视觉特征。
4. **单一任务限制**：前序工作 [3] 仅支持二分类分割任务，缺乏面向多类别分类、目标检测和可解释性闭环的综合平台。

## 核心贡献（创新点）
1. **文化遗产导向的端到端开源 CV 平台**：将数据集管理、模型训练、评估、推理集成于单一 Web 界面；与 Roboflow/Ultralytics 等商业云平台本质不同在于完全开源且支持纯本地部署，不依赖外部服务。
2. **多用户 + 联邦身份 + 模块化存储架构**：基于 Docker + Kubernetes 实现并发多用户隔离，支持 OAuth 2.0 / OpenID Connect 对接 Keycloak、Directus 等外部身份服务，并将本地目录作为外部数据服务的缓存层；与 ClearML/MLflow 等 MLOps 框架相比，重点突出"数据不出境"的可自托管特性。
3. **Grad-CAM + VLM 双通道可解释性闭环**：推理阶段自动生成 Grad-CAM 热力图，再送入 Qwen2-VL-2B 生成自然语言解释，辅助 CH 专家判断模型是否聚焦于考古相关区域；区别于普通可视化解释，该系统将解释嵌入假设检验工作流。
4. **实验考古学假设检验验证**：在泥板纺织压痕数据集上完成材料分类、工艺分类和分割三项任务，由 CH 专家在无 ML 背景指导下独立训练验证，证明平台可支撑考古假设检验闭环。

## 方法详解
- **前端 UI**：基于 Flask 实现，提供数据集导入/管理、训练配置、模型评估和推理界面，内含参数描述与架构推荐引导，降低非专家用户的配置门槛。
- **训练编排**：通过 Kubeflow 在 Kubernetes 集群上调度训练任务，Katib 负责并行超参数搜索（支持随机/网格/Bayes 策略），用户可自定义搜索区间和数据增强策略。
- **支持任务与模型**：
  - 分类：ResNet、EfficientNet、MobileNetV2、ShuffleNetV2、ConvNeXt（支持从零训练与预训练微调）
  - 分割：U-Net、DeepLabV3+、PSP-Net
  - 检测：YOLOv8/YOLO11/YOLO26（Ultralytics）
  - 所有任务均支持多分类
- **优选策略**：Katib 完成后按任务主指标（mIoU / mAP@50–95 / Accuracy）自动选取最优 checkpoint 并存储元数据，目标可切换为最小化训练/验证损失。
- **无状态推理**：每次推理请求启动临时 Docker 容器加载模型执行预测，完成后销毁，保证训练-推理环境一致。
- **可解释性管线**：
  - Grad-CAM 生成热力图，标注模型决策关注的图像区域
  - VLM 助手（Qwen2-VL-2B-Instruct）接收原始图像 + Grad-CAM 图 + 预测元数据（预测标签、置信度、概率分布、真实标签），按固定 prompt 模板输出结构化 JSON 解释，说明模型偏向预测类别的原因
- **多用户管理**：用户认证可本地管理或委托第三方身份提供商；每个用户拥有独立持久 ID，数据集/实验/checkpoint/推理结果按用户隔离，共享底层计算与存储资源。
- **数据存储层**：
  - 单机独立模式：所有资产（数据集、实验、模型、推理输入输出）落本地磁盘，零外部依赖
  - 外部服务模式：本地目录作为缓存层，通过内容寻址双向同步至外部服务（如 S3 + 关系型数据库），离线时自动 fallback 到缓存
- **部署形态**：全套 Docker 镜像分发；单机可独立运行；大规模部署时计算层与数据存储层解耦，通过 Kubernetes 横向扩展多 GPU worker。

## 实验与结果
- **数据集**：实验考古学泥板纺织压痕数据集，由华沙大学考古学家制作并标注（近距显微/Dino-Lite 成像），CH 专家使用 CVAT + SAM 完成分割标注。
  - 材料分类：1927 张图像
  - 工艺分类：1837 张图像
  - 分割：387 张图像（含人工 mask）
- **实验设置**：每种任务枚举所有可用模型，超参范围如 Tab.1 所示；重复 5 次不同 train/test split 取均值±标准差。
- **分类结果（Tab.2）**：
  | 模型 | Material Acc (%) | Technique Acc (%) |
  |------|-------------------|-------------------|
  | ResNet18 | 74.88 ± 1.04 | 83.09 ± 2.09 |
  | EfficientNetB0 | **76.32 ± 1.21** | **83.68 ± 1.89** |
  | MobileNetV2 | 74.32 ± 1.33 | 82.89 ± 2.37 |
  | ShuffleNetV2 | 72.28 ± 1.98 | 80.10 ± 2.66 |
- **分割结果（Tab.2）**：
  | 模型 | mIoU (%) |
  |------|---------|
  | U-Net | 90.02 ± 1.79 |
  | DeepLabV3+ | **90.47 ± 1.78** |
  | PSP-Net | 84.20 ± 3.60 |
- **推理验证（Tab.3，假设检验证据）**：
  - 材料分类总体准确率：**77.53%**（Flax 73.03%, Nettle 68.75%, Lime Bast 78.73%, Wool 87.45%）
  - 工艺分类总体准确率：**85.57%**（Drilling 88.58%, Spinning 90.80%, Splicing 67.91%）
  - 误分类集中在视觉相似类别（Nettle、Splicing），CH 专家确认这些类别本就在视觉上难以区分，说明模型利用了标签相关视觉特征而非仅数据集偏差。
- **结论**：不同 split 结果稳定；EfficientNetB0 和 DeepLabV3+ 分别为分类与分割最强模型；平台支持 CH 专家从零数据集到可复用模型的完整闭环；结果定位为"工作流验证证据"而非基准竞赛声明。

## 相关工作脉络
1. **Roboflow / Intel Geti / Ultralytics Platform**：商业 or 闭源云 CV 全栈平台，提供annotation→train→deploy一体化，但数据默认上云、自托管受限；AmalthAI 在同功能范畴内以开源+自托管为核心差异。
2. **MLflow / ClearML / Kubeflow+Katib**：开源 MLOps 框架，侧重实验追踪和 Pipeline 编排，但不提供面向非技术用户的 no-code CV 任务封装和可解释性闭环；AmalthAI 将其作为底层组件集成，向上提供领域适配层。
3. **前序工作 [3]（CAA 2025）**：单一用户二分类分割框架；本文扩展到三任务多分类、多用户联邦架构和 Grad-CAM+VLM 解释闭环，定位从"原型框架"升级为"生产可用平台"。
4. **考古 CV 应用（分类[50]、建筑[32]、陶瓷[26]、纺织品[45]、损伤评估[12]）**：多数为任务专用模型、需编程背景；AmalthAI 提供通用多任务平台以支撑此类研究的可复用实现。
5. **Grad-CAM [43] / Qwen2-VL [49]**：各自为独立技术；本文的关键差异是将两者串联构建"模型决策 → 可视化 → 自然语言解释"的解释链，服务于 CH 专家的假设检验而非通用 ML 调试。

## 局限性与未来方向
1. **高级训练选项不可见**：自定义 loss、optimizer、scheduler 等底层参数未暴露给终端用户，限制了细粒度实验控制。
2. **数据划分需预分区**：当前要求用户上传前手动完成 train/val/test 划分，平台不做数据分布自检，非专家易因划分不当过拟合。
3. **仅支持 2D RGB 图像**：未引入多光谱/高光谱输入，而后者在考古材料鉴别中已被证明可提供超越可见光的判别信息。
4. **缺少角色权限控制**：所有用户共用同一套界面能力，无法为专家用户提供无感进阶路径。
5. **未来方向**：
   - 上传阶段加入自动数据健康检查（小样本告警、类别不平衡提示、split 合理性评估）
   - 引入 Role-Based Access Control（RBAC），高级用户可见高级配置
   - 扩展支持多光谱图像输入
   - 扩展模型库（TorchVision 已预留接入接口）

## 研究启发与可借鉴点
1. **可解释性闭环设计**：Grad-CAM + VLM 的组合将"哪里看"和"为什么"串联，形成面向领域专家的"质疑-验证"回路；可迁移到医疗影像、工业缺陷检测等需要专家审核的 no-code AI 场景。
2. **无状态推理容器化**：每次推理启动一次性临时容器、执行后销毁，保证训练-推理一致且资源隔离；适合需要高并发或多租户隔离的平台。
3. **双模数据存储层（本地缓存 + 外部服务双向同步）**：在"数据不出机构"与"跨机构协作"之间取得平衡，对文物数字化、受版权约束图像数据集尤为实用。
4. **平台即假设检验工具**：将 CV 训练直接嵌入考古学的"假设检验"范式（hypothesis testing），而非仅作为图像处理工具；可启发其他人文社科领域的 AI 工作流设计。
5. **配置引导式 UI**：参数描述、典型用法、架构权衡建议 inline 展示，并链接文档；降低非技术用户认知负担的同时保留专家扩展路径，值得其他 no-code ML 平台借鉴。

## 关键术语表
- **AmalthAI**：本文提出的开源计算机视觉平台，面向文化遗产领域专家，提供无代码分类/分割/检测全流程支持。
- **Cultural Heritage (CH)**：文化遗产，指具有历史、艺术或科学价值的物质与非物质遗产，本文中特指考古文物与遗址图像分析场景。
- **Kubeflow / Katib**：Kubeflow 是基于 Kubernetes 的 ML 流水线编排框架；Katib 是其内置的超参数优化组件，支持并行 trial 与多种搜索策略。
- **Grad-CAM**：基于梯度的类别激活映射方法，通过计算输出对卷积层特征图的梯度来生成热力图，定位模型决策所依赖的图像区域。
- **Vision-Language Model (VLM)**：同时理解图像与文本的多模态模型；本文采用 Qwen2-VL-2B-Instruct 对 Grad-CAM 结果与原始图像生成结构化自然语言解释。
- **mIoU / mAP@50–95**：语义分割常用指标（各类别 IoU 均值）和目标检测常用指标（IoU 阈值 0.50–0.95 的 AP 均值）。
- **Self-hostable**：支持完全在用户自有基础设施上部署，不依赖第三方云服务；对受数据主权约束的机构至关重要。
- **Hypothesis testing in archaeology**：考古学中的假设检验，指通过可观测证据验证专家提出的命题；本文用 CV 模型预测结果检验"泥板压痕能否保留纺织物材料与工艺信息"的考古学假设。

## 可复现要素
- **数据集**：实验考古学泥板纺织压痕数据集；代码仓库已公开（https://github.com/TEXTaiLES/AmalthAI），数据集公开状态论文未明确说明，仅提及由华沙大学考古团队制作并在 TEXTaiLES/ExplorTIC 项目中使用。
- **代码**：已开源（GitHub: TEXTaiLES/AmalthAI）。
- **权重**：使用预训练权重（ResNet/EfficientNet/MobileNet/YOLO/U-Net/DeepLabV3+/PSPNet），论文未发布专属微调权重。
- **关键超参**：
  - 分类：lr 0.001–0.1，batch 4–16，epochs 30–50
  - 分割：lr 0.001–0.1，batch 8–16，epochs 20–30
  - 训练指标优选：mIoU（分割）/ mAP@50–95（检测）/ Accuracy（分类）
- **评测硬件**：单卡 NVIDIA RTX 5090 GPU + 64 GB RAM；建议多用户部署时 VLM 独占单卡，训练/推理分散至其他 GPU worker。
